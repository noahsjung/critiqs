Review without the screenshot back-and-forth

Most build reviews still happen after the fact, in chat. Critiqs moves them onto the page itself, where anyone on the team can take part.

One comment on the page, not a screenshot and five messages

A screenshot in chat starts a round of questions: which customer, which build, which tab. A comment on the build answers them before anyone asks.

Join the review without setting anything up

Today, taking part means tracker accounts, repository access and a copy of the app running on your computer. With Critiqs, a reviewer opens a link.

Feedback from every build, in one place

Give staging, preview and QA builds the same project ID. Every comment lands in one list, tagged with the build it came from.

Everyone can review the build, not only developers

Today, only someone who can run the app sees a change before it ships. With Critiqs, product, design and clients comment on the same build, and a coding agent can pick up the threads.

Every comment keeps the screen behind it

Each comment is pinned to an element, with a capture of what the reviewer saw, so nobody has to explain a screenshot.

Point at it instead of describing it

Switch to Comment mode and click any element. Your comment is pinned to it for everyone, with a capture of what you saw.

Every thread remembers where it was left

Every thread saves a capture and the page it was left on. When your app tells Critiqs which tab, dialog or record is open, picking a thread brings that view back and opens the discussion beside the element.

Hand it to a developer or a coding agent

Select threads and export them as Markdown for people or JSON for tools. Coding agents connect through the Critiqs MCP server, read each thread with its context, and reply in it.

Try a change on the page before anyone builds it

Describe a design change in plain words: wording, spacing, colors or layout. Critiqs AI edits the HTML and CSS of a frozen copy of the page, never your app, so your feedback arrives with the picture you had in mind.

  1. Ask in your own words

    Start a thread on the page or on one element, such as “make this a quieter outline button”. Add existing comments for Critiqs AI to read.

  2. Watch the page change

    Critiqs AI reads the page and rewrites the copy’s HTML and CSS, showing each step as it works. Text, spacing, colors and layout update in place; your real app stays as it is.

  3. Attach it to the feedback

    Every version stays in the thread, so developers and agents see exactly what you meant. Hold Compare to see the live page again.

Add it to your staging build

Two commands to install. Critiqs Cloud handles storage, sign-in and email, so there are no keys to enter.

  1. 1

    Add Critiqs to your app

    Setup adds <Critiqs /> where your app renders, signs you in, and creates your project.

    npm install critiqs-react
npx critiqs-react init
  2. 2

    Share the link

    Set the project ID in your staging, preview and QA build settings, leave it out of production, and send the link. Builds that share an ID share one set of threads. Optionally pass your tabs, records and build version so threads can bring their view back.

  3. 3

    Build from the threads

    Export threads for an issue, or add the Critiqs MCP server to your coding agent so it reads them with their context.

    npx critiqs-react mcp

Questions before you install

Which apps does Critiqs work with?
Any React 18 or 19 app, including Vite, Next.js (App Router or Pages Router), Remix, Create React App, or your own setup. React and React DOM are its only peer dependencies, and setup needs Node.js 20 or later.
Do reviewers need an extension, an account or a password?
No. They open your staging or preview link in any browser and sign in with their email address and a one-time code. Their first sign-in creates their account, and there is nothing to install.
Does Mockup mode change our code?
No. Mockup mode freezes the current page into a copy in the browser, and Critiqs AI only changes that copy. Your running app stays as it is until a developer or coding agent builds the change. Mockup mode runs on Critiqs Cloud or a team’s own Convex deployment.
How do coding agents use the feedback?
npx critiqs-react mcp gives your agent tools that list threads with their context, read whole discussions, fetch captures, read mockups, and reply marked “via coding agent”. Agent tools work with Critiqs Cloud and Convex deployments. You can also export threads as Markdown or JSON.
Where is the feedback stored?
On Critiqs Cloud by default. Teams that need their own storage can run Critiqs on their own Convex deployment.
Will our real users see Critiqs?
Only where you turn it on. In Vite and Next.js apps, setup adds requireProjectId, so Critiqs appears only in builds that set a project ID. A build without one adds nothing to the page and contacts no server.
What happens to comments when the UI changes?
If Critiqs can still find the element, the pin follows it. If the element moved behind a tab or was removed, the thread stays in the sidebar with its saved capture and context, and threads from earlier builds are kept.
Does Critiqs need AI?
No. Commenting, threads, mentions, tags and exports never depend on AI. Mockup mode, automatic tag grouping and plain-language search use Critiqs AI, or your own key for OpenAI, Anthropic, Google Gemini, OpenRouter or Vercel AI Gateway.
