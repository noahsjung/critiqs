# critiqs-react

## 0.3.0

### Minor Changes

- 30043bd: Let each app and each deployment choose its own Critiqs project. The new optional `requireProjectId` property keeps `<Critiqs />` off the page, with no backend requests, until `projectId` is a valid project ID, never uses a project remembered in the browser, and reports a wrong or unreachable configuration in the browser console instead of showing visitors setup or errors. In Vite and Next.js apps, `critiqs init` now writes `<Critiqs projectId={import.meta.env.VITE_CRITIQS_PROJECT_ID} requireProjectId />` (or `process.env.NEXT_PUBLIC_CRITIQS_PROJECT_ID`) and sets the variable in `.env.local`, so each deployment sets its own in its build settings; other builds, and components that already name an ID, keep a literal ID. In a workspace, run init once per app with `--dir`: each app gets its own variable and project, and init at the workspace root lists the apps instead of choosing one. `--env-file` names the `.env` file when Vite's `envDir` can't be followed, and doctor, `--json`, and the MCP tools report the variable and its file. Components without `requireProjectId` behave as before.
- 30043bd: Set up Critiqs in any React app with one command. `npx critiqs-react init` adds `<Critiqs />` where a React root, Next.js App Router layout, or Pages Router App renders (or where `--entry` and `--mount` say), uses Critiqs Cloud without asking, keeps or reuses existing projects, and reports what remains for local and deployed reviewers, including missing or local-only review addresses. `--remote` approves sign-in from a browser on any device with a short setup code, `doctor` separates configuration from observed behavior and treats AI as optional, and both print JSON with `--json`. The package's entry is now marked `"use client"`, so a Next.js server layout can import it directly. Published under the MIT license. Backends deployed from this version add the sign-in routes for remote approval and report whether a project's review address is local-only; older backends and packages keep working.

### Patch Changes

- 9f865f5: Show open threads from all screens in a fresh sidebar, including read and unread threads. Selecting the current screen still narrows the list.

## 0.2.0

### Minor Changes

- 26d665e: Mention emails show the thread's capture or attached screenshot inline and its whole discussion in order, with authors, times, and a link to each message. Emails are sized to the mail service's limit and retries send identical content. The self-hosted server and the deployable Convex functions both include this.
- a1874d8: Add optional private Cloudflare R2 storage for screenshots, with Convex retaining metadata and access checks. Existing Convex screenshots remain readable, and mention emails can include screenshots from either storage provider. Deploy a matching client with authenticated upload support before enabling R2 on an existing prototype.
- e6b97bb: Reviewers can write hashtags such as `#wording` in comments, with `#` suggestions and tags that filter the sidebar; the server derives every thread's tags from its text, keeping explicit tags and older components working. Project owners organize shared tag groups, which filters expand, and new tags can be grouped automatically. The sidebar searches feedback by words and tags, or by plain questions with insights that cite their threads when the project has AI: Critiqs-managed AI or the project's own OpenAI, Anthropic, Google Gemini, Vercel AI Gateway, or OpenAI-compatible provider, whose keys are stored encrypted on the backend. V returns to Browse mode, keeping a comment draft, and Ctrl or Cmd with backslash hides or shows all of Critiqs. Backends report protocol 5: deploy the current backend functions before upgrading the component, set `CRITIQS_AI_ENCRYPTION_KEY` to let owners connect providers, and run `npx convex run tags:backfill` once on an existing Convex deployment. Self-hosted SQLite databases upgrade on start, and `createCritiqsHandler` accepts an optional `ai` setting.

### Patch Changes

- e6b97bb: Remove the fixed preset tag choices below new-comment and reply inputs. Tags are entered through hashtags, with suggestions and the live draft preview; existing tags remain available in filters.
- e6b97bb: Highlight hashtags directly inside comment, reply, and edit inputs instead of repeating them as draft pills below the text.
- 122680b: Elements marked `data-critiqs-mask` are now covered in the copy of the page itself, so masked content that moves or scrolls while a capture is made is never saved; their text, images, field values and generated text are left out wherever they are. Captures no longer paint gray over where masked elements were when the capture began.
  
  Directly marked canvas, video and iframe elements fail automatic capture safely because the renderer replaces them without their privacy marker. Mark a containing element to cover those regions in an automatic capture.
- e6b97bb: Show hashtags in comment, reply and edit inputs as padded pills inside the text, with typing, line breaks, paste, undo and suggestions working as before; posted text is unchanged. Name the comment placement choices "This component" and "Matching components", each with its own help button that explains it without changing the choice.
- e6b97bb: Remove the trailing hashtag insertion button from comment, reply and edit inputs. Type `#` directly to open tag suggestions and preview hashtags in the draft.
- 122680b: Saving a comment no longer freezes host apps whose design system defines thousands of CSS custom properties: automatic captures copy each element's standard computed styles, which already resolve `var()`, and give the page a turn while copying. A capture that runs past its ten-second limit now actually stops, also while the renderer waits on media that never loads, and leaves no hidden frame behind. A copied page that can't be drawn, or a capture finished after `getContext` reported another screen or view state, saves the comment with a failed capture instead of a blank or mismatched image. Screenshots already saved are unchanged.
- 122680b: Keep element lookup conservative when a page changes: sibling positions and matching text cannot identify a shifted element reliably. Hosts can give changing preview headings stable `data-critiqs-id` values so comments survive tooltip or dialog insertions; missing elements do not jump to lookalikes elsewhere.
- 122680b: A thread's saved context and the messages about its view now shorten view state values longer than 60 characters, such as an unsaved draft a host records, instead of printing them in full. Saved threads and exports keep the whole value.
- 122680b: Show in prototype, and opening a thread from the list or a link, now go to the screen and view state where the thread was left, even when a matching element is visible in the current view. After `restoreContext`, Critiqs waits for `getContext` to report the saved screen and view state before showing the target; otherwise it explains what is missing beside the saved context. Keys a thread lacks because it was saved before the host reported them are left to `restoreContext` once it has run; report each key with null when nothing is open so newer threads name their whole view. Return a promise from `restoreContext` to wait for slower content. The open thread keeps its pin under any status filter. Automatic captures now leave out every mounted Critiqs, not only the one saving the comment; screenshots already saved are unchanged.
- e6b97bb: Show tags in one look everywhere: hashtags being typed, posted hashtags, and tag chips in the sidebar, search results, suggestions and tag settings share the same pill and colors, and chips read as hashtags with a leading `#` (multiword tags as `#UX-copy-change`); filtering by a chip is unchanged. The chosen comment placement is now filled in the accent color with an outline, so it no longer looks disabled.
- e6b97bb: Give inline draft hashtags rounded pill outlines. Clarify comment placement with shorter choices and help available on hover, focus, or tap.
- 122680b: Pins and the thread window now count only the part of a target the open sidebar doesn't cover, so a pin is never drawn underneath the sidebar. When Show in prototype reveals a target entirely behind the sidebar, the sidebar closes so the target, its pin and the thread show.
- 122680b: Wait for a restored view's finite transitions before scrolling to feedback. A sliding preview no longer receives an extra horizontal scroll that hides its selected screen and comment pin. Obsolete requests remain cancellable; a transition that does not finish is reported instead of claiming the target is shown.
  
  Follow replacement targets and their transitions within the same deadline before scrolling.
