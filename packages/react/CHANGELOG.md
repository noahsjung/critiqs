# critiqs-react

## 0.4.0

### Minor Changes

- 36f081b: Backends gain three additions for the browser extension, and for any setup flow that creates projects. Adding or removing one address (`projects:addAddress`, `projects:removeAddress` on Convex; `addProjectAddress`, `removeProjectAddress` on the self-hosted server) changes a project's address list in one step, so two people adding at once both keep their address; owners only, with the same checks and 20-address cap as the whole list. `projects:manageable` (`manageableProjects`) lists the projects whose address lists the signed-in person may change: every project in organizations they're an admin of, and the projects they created while a member. `projects:create` (`createProject`) takes an optional `idempotencyKey`: a retry with the same key by the same person within a day returns the same project instead of making another, and creates without a key work as before. Backends report these with `addressEdits` and `createKeys` at `/critiqs/config`; the protocol stays 5 and older components keep working unchanged. Deploy the matching backend; the self-hosted server's database moves to schema version 13 when it starts.
- b4c9908: Project setup shows a project's owners its address list, the sites where the Critiqs extension finds the project, on backends that report `addressEdits`. Each address has **Remove**, and a field adds an origin or a pattern such as `https://*-acme.vercel.app`; each change saves at once. The transport adds `useProjectAddresses`, `addProjectAddress`, and `removeProjectAddress`. `parseProjectAddress` in `@critiqs/core` now reads a pattern the same in every browser: Chrome writes a `*` in a host as `%2A`, which made it refuse every pattern there. Backends now refuse a pattern that covers a whole shared domain or public suffix, such as `https://*.vercel.app`, `https://*.github.io`, or `https://*.co.uk`, using the Public Suffix List with its private section; `https://*-acme.vercel.app` and `https://*.acme.com` are still accepted. A pattern like that saved earlier stays on the list for its owners to remove, but the extension's lookup no longer finds any project by it, and a match reached only through a pattern of a project the person merely opened is offered as a choice, never shown at once.
- da2260b: Projects can keep an address list for the coming browser extension: origins such as `https://acme-proto.vercel.app`, or patterns such as `https://*-acme.vercel.app`, set by the project's owners. The extension will find a page's project by its origin, searching only projects in the person's organizations and projects they opened through an install; another team's project with the same origin is never shown or revealed. The installed component now records, once per page load, that the signed-in reviewer opened its project, on backends that report `addressLists` at `/critiqs/config`. The backend protocol stays 5: these are new calls (`projects:setAddresses`, `projects:addresses`, `projects:recordOpened`, `projects:findForOrigin` on Convex, and the same calls on the self-hosted server), and older components keep working unchanged. Deploy the matching backend; the self-hosted server's database moves to schema version 12 when it starts.
- b4c9908: Backends refuse an address pattern over a shared domain unless at least four letters or digits of the site's own name sit beside its `*`: `https://*a.vercel.app` and `https://*-app.vercel.app` are refused, `https://*-acme.vercel.app` is still accepted. Shared hosts the Public Suffix List misses, such as `glitch.me` and `koyeb.app`, now count as shared domains. Backends that report `addressNotes` answer `projectAddressNotes` with the addresses in a project's list that match no site now, and project setup marks each one, saying to remove it and what to add instead; its example pattern is now one the list accepts.
- 965f969: Coding agents can read a project's feedback with its context. The MCP server (`npx critiqs-react mcp`) adds `critiqs_comments`, which returns threads with their whole discussions and the context to find them in the prototype and its code, filtered by status, author, time, tag, screen, or text; `critiqs_thread`, with mentions, reactions, and who last resolved or moved it; and `critiqs_screenshot`. A computer signs in once with `npx critiqs-react sign-in` (or the `critiqs_sign_in` tool), approving with a code from any device, and stays signed in for agents until `npx critiqs-react sign-out`, 30 days without use, or 90 days. Messages from the backend now include `authorId`, so feedback can be told apart by author even when two people share a name. Deploy the matching backend for code approvals that keep a computer signed in; older backends are refused with what to do instead.

Backends report this with `personalAi` in their configuration; the interface for it comes in a later release, and existing projects and older components keep working unchanged.
