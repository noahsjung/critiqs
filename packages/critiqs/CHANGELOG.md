# critiqs

## 0.5.0

No changes in this release.

## 0.4.0

### Minor Changes

- b4c9908: Project setup shows a project's owners its address list, the sites where the Critiqs extension finds the project, on backends that report `addressEdits`. Each address has **Remove**, and a field adds an origin or a pattern such as `https://*-acme.vercel.app`; each change saves at once. The transport adds `useProjectAddresses`, `addProjectAddress`, and `removeProjectAddress`. `parseProjectAddress` in `@critiqs/core` now reads a pattern the same in every browser: Chrome writes a `*` in a host as `%2A`, which made it refuse every pattern there. Backends now refuse a pattern that covers a whole shared domain or public suffix, such as `https://*.vercel.app`, `https://*.github.io`, or `https://*.co.uk`, using the Public Suffix List with its private section; `https://*-acme.vercel.app` and `https://*.acme.com` are still accepted. A pattern like that saved earlier stays on the list for its owners to remove, but the extension's lookup no longer finds any project by it, and a match reached only through a pattern of a project the person merely opened is offered as a choice, never shown at once.
- b4c9908: Backends refuse an address pattern over a shared domain unless at least four letters or digits of the site's own name sit beside its `*`: `https://*a.vercel.app` and `https://*-app.vercel.app` are refused, `https://*-acme.vercel.app` is still accepted. Shared hosts the Public Suffix List misses, such as `glitch.me` and `koyeb.app`, now count as shared domains. Backends that report `addressNotes` answer `projectAddressNotes` with the addresses in a project's list that match no site now, and project setup marks each one, saying to remove it and what to add instead; its example pattern is now one the list accepts.
- 5ac9651: Angular apps can add Critiqs with `provideCritiqs()` from the new `critiqs-angular` package (setup adds it to `src/app/app.config.ts`); it runs only in the browser, outside Angular's zone, loads after the app starts, and with Angular Router names each thread's route (`users/:id`) and navigates back to it when a thread is opened (`router: false` turns this off).
- 4a0684f: Astro sites get Critiqs on every page from one line in `astro.config` (`integrations: [critiqs()]` from the new `critiqs-astro` package), reading the project ID from `PUBLIC_CRITIQS_PROJECT_ID` or the config, staying open across `<ClientRouter />` navigations, naming each thread's page by its route (`items/:id`) and opening it again from a thread (`router: false` turns this off; your own `restoreContext` can fall back to `restoreRoute` from `critiqs-astro/client`); setup can add it to `astro.config`.
- 3363e81: `npx critiqs init` sets up Critiqs in any supported framework: it finds the app's framework, adds Critiqs where the app renders, and names the framework's package to install. It updates the Critiqs the code already has, even under another name, instead of adding a second, and in a Vite app it writes the project ID to the `.env` file Vite reads first. The `critiqs` command, its MCP server, and `critiqs/server` now come from the shared `critiqs` package; `npx critiqs-react <command>`, `npx critiqs-react mcp`, and `critiqs-react/server` keep working unchanged.
- d1e2f8d: Add `critiqs`, Critiqs for any web app: a script tag that adds Critiqs from `data-project-id`, `<critiqs-app>` for server-rendered pages, and `mountCritiqs()` for framework packages, with `setContext()` to report the current view and `routeContext()` and `routePath()` for routers. `<Critiqs />` in `critiqs-react` now uses the same mounting code, with no change in behavior.
- 412c467: A project's owner can now change its preset tags, which typing `#` suggests after the tags reviewers used most recently: in **Tags and AI**, the **Tags** tab (formerly **Tag groups**) lists them in order, with **Add preset**, and **Change…** on each to move it up or down, rename it, or remove it. Rename, move, and remove act on the preset chosen even when the list changed in another window meanwhile. Presets follow the tag rules (1 to 50 characters, starting with a letter, with letters, numbers, spaces, `-`, and `_`; no two alike; up to 50). Threads keep the tags they already have: a renamed or removed preset stays on them as an ordinary tag, still in filters. Among tags not used yet, `#` now suggests presets in the project's order instead of alphabetically. Backends gain `tags:setPresets` (Convex) and `setPresetTags` (self-hosted server), which require the list being changed as `previous`, and report `presetTags` at `/critiqs/config`; the editor appears only on backends that report it, the protocol stays 5, and older components keep working unchanged. Deploy the matching backend; the self-hosted database needs no migration.
- 865af11: Jira Cloud connects through Atlassian OAuth sign-in only; pasted Jira API tokens are refused, and deployments without an Atlassian OAuth app omit Jira from `/critiqs/config`.
- 75cc0dc: Onboarding can say **Connected**. Critiqs, loading on the prototype with a project ID, tells a backend that reports `connections` in its configuration, at most once an hour per browser and before anyone signs in, by posting the project ID to `/critiqs/connected`. The backend reads at most 200 bytes, counts a report only from the project's review address or an address its list matches, and keeps the latest one, at most once every ten minutes. The extension's side panel and a developer's own computer don't count. Onboarding's setup screen and the developer's setup page wait for it, then say Connected with where and when, and the project's owners can clear it (`clearConnected`). Setup pages return it as `connected`. Deploy the matching backend. The self-hosted SQLite store adds two columns on start (schema version 19) and marks projects that already have threads connected at their first thread; on Convex, run `npx convex run onboarding:backfillConnected` once after deploying.
- 8254f5b: Privacy hardening for project setup, review links, thread links, and extension discovery:
  
  - Hide project existence and names from signed-in outsiders on `/setup/<id>` (`onboarding:projectSetup` / `projectSetup` returns `not-found` for non-members) and `/review-links/<id>` (loads project metadata only after the owner-only review-links query succeeds).
  - Move thread-page links from `/t/<key>` to `/t#<key>` so thread keys stay out of web-host request logs (legacy `/t/<key>` links continue to open and parse).
  - Restrict browser extension project discovery (`findProjectsForOrigin`) to organizations the signed-in person belongs to, and stop recording opened projects from installed components and review links (keeping `recordProjectOpened` / `reviewLinks:recordOpened` as wire-compatible no-ops).
- 957ce10: Add Critiqs for Django (`pip install django-critiqs`, then `{% critiqs %}` in your base template) and Flask (`pip install flask-critiqs`, then `Critiqs(app)` and `{{ critiqs() }}`), which read the project ID from `CRITIQS_PROJECT_ID` on each request and report each page's route as its screen, and setup that adds either to an existing app.
- 639ea04: Add Critiqs to Ruby on Rails apps with the new critiqs-rails gem: `<%= critiqs_tag %>` in the layout shows Critiqs wherever CRITIQS_PROJECT_ID is set and reports each page's route, and `bin/rails generate critiqs:install` or `critiqs init` adds it for you.
- 70461a2: `npx critiqs share <folder>` uploads a static build and prints a review link for it, so people can review a prototype that has no address they can reach, with nothing installed. Only the project's owners can share; `critiqs share list` and `critiqs share delete <id or link>` manage shared builds, which last 7 days by default (`--expires`, 1 to 30). The backend checks every file again (no source maps, hidden files, files in `__critiqs/`, or anything that isn't a static web file; at most 1,000 files and 50 MiB), stores each only when its size and SHA-256 match, and serves the build through the review proxy under the project's review access until it expires or is deleted. Comments on a shared build keep a `https://<id>.build.invalid` address that never contains the link.
- a030688: Solid and SolidStart apps (Solid 1.9 or 2) can add Critiqs with `<Critiqs />` from `critiqs-solid`, or from `critiqs-solid/router` in apps with Solid Router so threads name routes such as `users/:id` and opening one navigates there, and Critiqs's setup adds it to `src/App.tsx` or SolidStart's `src/app.tsx` with the project ID read from `VITE_CRITIQS_PROJECT_ID`.
- 31ba122: Svelte and SvelteKit apps can add Critiqs with `critiqs-svelte`: `<Critiqs />` from `critiqs-svelte` (Svelte with Vite) or `critiqs-svelte/kit` (SvelteKit, which also names threads by route and goes back to them with `goto`) runs only in the browser, and `npx critiqs init` adds it to `src/App.svelte` or `src/routes/+layout.svelte`, reading the project ID from `VITE_CRITIQS_PROJECT_ID` or `PUBLIC_CRITIQS_PROJECT_ID`.
- da1dd80: Thread pages return `connectedAt` with their project, and how each thread was left (`prototype.madeWith`: `install`, or `extension` when the panel ran in the browser extension; absent on threads from before). Components send `madeWith` on new threads to backends that report `threadMadeWith`. On the Critiqs website, a thread page offers the Critiqs extension beside **Open in prototype** only for a thread left with the extension, saying whether the project is installed now; threads left with an install, including every thread from before, open where they were left. `@` in its reply box suggests the people in the thread. Whom someone may mention now follows their standing in the project, wherever they write from: the project's team mentions anyone in it who can still review it, and someone outside the team mentions the team and the people in the thread they write in (in a new thread, the team). Mention suggestions (`participants`) take the `threadId` being replied in or edited and offer exactly the people a mention is accepted for there; components send it to backends that report `threadMentions`, so in the panel and the extension two people outside the team in one thread are offered each other. The self-hosted database gains a column for how each thread was left (migration 21); existing threads keep it empty.
- 3b5b7e4: A thread's linked tickets now travel with it. Mention and reply emails name each ticket under the thread's status (tracker, key, status, and address; only a web address becomes a link). A status Critiqs can no longer check reads "last known" in emails, exports, and `critiqs_thread`, as in the thread window. The Markdown export adds a "Ticket:" line per ticket to each thread's context (or "Tickets: none"), and the JSON export adds an optional `tickets` array (`tracker`, `key`, `title`, `status`, `lastKnown`, `url`) to each thread, keeping schema version 1. The `critiqs` CLI's MCP tool `critiqs_thread` adds `tickets` (key, title, status, `lastKnown`, address, who linked it and when). The backend's export pages carry `thread.tickets`, and emails read them, only where the backend has tickets; the self-hosted SQLite server is unchanged. Deploy the matching backend for emails and exports to include them.
- ab5c1f9: Add Critiqs to Vue and Nuxt apps: `critiqs-vue` adds a `<Critiqs>` component for Vue 3, `critiqs-nuxt` is a Nuxt module that only needs adding to `modules` (with the project ID from `NUXT_PUBLIC_CRITIQS_PROJECT_ID`), both report each Vue Router route as the screen and open a thread's route again (Nuxt apps can pass their own `getContext` and `restoreContext` through the `critiqs:options` hook), and setup can now add either to an app.

### Patch Changes

- 75cc0dc: A Connected report from the project's address written with a final dot (`https://acme-proto.vercel.app.`) is kept as the address itself. Both backends drop a report that can't count before reading anything; on Convex such a report no longer runs a mutation. An address saved before its project moved to another organization no longer counts for Connected, as it already didn't for the extension's lookup.
- 7d9071c: `npx critiqs init` and `doctor` on Django also look for `{% critiqs %}` in the folders `TEMPLATES["DIRS"]` lists (written as `BASE_DIR / "folder"`, `os.path.join(BASE_DIR, "folder")` or a string), so a run without `--entry` after one with it no longer adds a second tag to another template.
- 9aa4d5b: Critiqs now reads whether a backend reports `addressEdits` and `createKeys` at `/critiqs/config`, which the browser extension needs. Nothing changes for host apps.
- 7d9071c: Page copies for mockups leave out values the page never shows, which only its scripts read (no script runs in a copy). Left out: the value of each hidden form field (`type="hidden"`, or a field with the `hidden` attribute that isn't displayed); HTML comments; the content of every `<meta>` tag except `viewport`, `color-scheme`, `supported-color-schemes`, `referrer` and `format-detection`, such as anti-forgery tokens, keys and descriptions; Inertia's `data-page`, Phoenix LiveView's `data-phx-session` and `data-phx-static`, Livewire's `wire:snapshot`, `wire:effects` and `wire:initial-data`, Turbo's `signed-stream-name` and Astro islands' `props`; and any other `data-*` or `prefix:name` attribute whose name contains `csrf` or `xsrf`, or whose value is JSON or a single token of 100 characters or more, unless the page's CSS names that attribute. Those tags and attributes stay, empty, so the copy looks the same. Still copied: text and visible form values, shorter `data-*` values, other attributes (such as a form's `action` address or a button's `value`), fields hidden only by CSS, and the addresses of the page's images and stylesheets. Copies made by earlier versions keep what they held.
- 0814566: Internal groundwork for the browser extension and review links: the messages Critiqs's page layer and panel will exchange, and the ways to carry them between documents. Nothing changes for host apps.
- 12c0616: Critiqs's interface now runs as two parts inside the package: a page layer that picks elements, draws pins, locates targets, captures the view, and calls `getContext` and `restoreContext`, and a panel with the toolbar, sidebar, threads, sign-in, and backend connection. Installed, both run in your page as before, so nothing changes in how you add or configure Critiqs or in what reviewers see. This prepares the browser extension and review links, which will run the two parts in separate documents.
- d1e2f8d: Critiqs keeps noticing page changes after a client router replaces the page's body, such as Astro's view transitions, so threads on content that appears later are still found.
- b469cef: Critiqs's panel can now run with a sign-in kept somewhere other than the page, with its sidebar filling a window of its own, and opening a given comment when it starts, which the browser extension's side panel needs. A shared link to a comment is now taken out of the page's address only when the address has one. Nothing changes for host apps: installed Critiqs signs in through its popup and leaves a strip of the page beside the sidebar, as before.
- 2b9f743: Hardening and policy updates:
  
  - Scope `release.yml` credentials (`persist-credentials: false`, `GH_TOKEN` only on the push/PR step).
  - Add `Content-Security-Policy: frame-ancestors 'none'` on `/allow-critiqs` and expand `scripts/site-host.test.ts` folder coverage.
  - Fix `packages/backend/scripts/setup-local.ts` startup polling, 503 retries, and signing-key preservation.
  - Set the pre-1.0 older-package support window to 6 months (`SUPPORT_MONTHS = 6`; 12 months at 1.0).
  - Add a daily per-project safety cap (`MAX_MENTION_EMAILS_PER_PROJECT_DAY = 1_000`) on mention and reply emails across all plans, including paid plans.
- 7a95d90: The Public Suffix List that address patterns are checked against is refreshed to version 2026-11-26_18-39-01_UTC. It adds eight shared hosts, so a pattern over `softr.app`, `staticrun.app`, `spheron.live`, `relumesite.ai`, `phronusercontent.com`, `xport.free`, `xport.host` or `xport.sh` now needs four letters or digits of the site's own name beside its `*`, as on other shared hosts.
- 213b564: Allow Critiqs: a site behind a bot wall or firewall can let one project's review links in. Its owners get a token for one exact origin (`reviewAllow:issue`, replaced with `rotate`), add a firewall rule matching the `Critiqs-Allow` header, publish the project's proof at `/.well-known/critiqs-allow.txt`, and **Check again** (`reviewAllow:check`) asks the review proxy to fetch the site with the token. Only after that does a review link send the token, and only to that origin. Onboarding now offers the ways to review without installing (a review link, sharing a build, Allow Critiqs) where the deployment's `/critiqs/config` reports them, sharing a build even before the prototype has an address, and a thread page's **Open in prototype** offers the project's review link for the comment's address.
- e0ffbbc: The address check's public-address rules and its pinned connection now live in one shared module, which the review-link proxy also uses; every host check now compares one spelling of a host, so a trailing dot or an empty label (`localhost..`) no longer reads as a different host than DNS sees. Host apps don't need to do anything.
- e0ffbbc: The page layer's protocol can now bound what it takes from a page layer in a frame Critiqs doesn't trust, such as a review link's prototype, so one forged message can't exhaust the panel's tab: entries, keys, occurrences across a whole state, and the address's scheme (http or https only) are all bounded. Installed Critiqs keeps taking what its host app reports, as before. Host apps don't need to do anything. Inside a review link's frame, Critiqs installed by the prototype itself now stays out quietly, since the review page runs Critiqs around the frame; installed Critiqs anywhere else is unchanged.
- 5c83648: `critiqs init` now gives Django, Flask and Rails apps their project for development, so Critiqs shows on the next page load with no environment variable to set by hand. Django gets `os.environ.setdefault("CRITIQS_PROJECT_ID", …)` in `manage.py`, beside Django's own default; Rails gets `ENV["CRITIQS_PROJECT_ID"] ||= …` at the end of `config/environments/development.rb` (or `.env` when the app uses dotenv); Flask gets `.env`, and flask-critiqs reads `CRITIQS_PROJECT_ID`, and only that key, from it when Flask's development server (`flask run`, `app.run()`) serves the page; it puts nothing in `os.environ`, adds no dependency, and production servers such as Gunicorn and Waitress never read it. An older plain `ENV["CRITIQS_PROJECT_ID"] = …` line in `development.rb` now gets the new ID instead of silently overriding it. A `CRITIQS_PROJECT_ID` set in the environment still wins, and deployments still show Critiqs only where they set it. Init's output also names installing the package and what each deployment sets once each, not twice.
- 7d9071c: `npx critiqs init` on Rails and Django rewrites a hand-written line that sets the project ID only when the line sets one string, with at most a comment after it (the comment stays) and no condition around it. Any other line (a condition, an expression, a block around it) is left as written: `init` sets the ID where the framework reads it first (`.env` with dotenv, otherwise its own default just before that line) and says which value the app uses and why. In a Rails app with dotenv, a plain `ENV["CRITIQS_PROJECT_ID"] = "…"` line in `config/environments/development.rb` runs after dotenv and wins over `.env`, so `init` updates that line. When `--project-env-file` names a `.env` file the app doesn't load (Django, or Rails without dotenv), `init` and setup warn that the app reads it only if its own code loads it; with dotenv they warn instead when a line in `development.rb` still wins over `.env`.
- 7d9071c: A Critiqs process that stopped while removing its sign-in lock could leave a `sign-in.v2.json.lock.<token>.gone` folder behind in Critiqs's config folder. The next process to take the lock now removes any such leftovers.
- 7d9071c: `critiqs sign-out` and the `critiqs_sign_out` tool hold this computer's sign-in lock for one request's time at most: the saved token and its saved replacement are ended together, and sessions kept aside after an interrupted renewal are ended after the lock is released, so another Critiqs process no longer gives up waiting while the sign-in service is slow. Sign-out now also reports a session another process kept aside while it ran, says "Forgot this computer's sign-in" rather than "Signed out" when the service had no session for it, and no longer says an older version's Critiqs Cloud sign-in was signed out when the service didn't confirm ending it. A command whose sign-in renewal is refused because another process signed out meanwhile now says this computer isn't signed in, instead of asking to try again.
- 7c63f5c: `critiqs sign-out` and the `critiqs_sign_out` tool no longer say the computer is signed out, or wasn't signed in, while a session they couldn't end stays saved: they say what is left and fail, so you can sign out again once the sign-in service is reachable. A sign-out that crosses another process's renewal now forgets the renewed sign-in too. A renewal answered after another process had already renewed again keeps that process's saved replacement, instead of dropping it and getting the session ended as stolen on the next renewal, and a renewal that lost a race ends its leftover session without keeping other processes waiting for the lock.
- d1e2f8d: Critiqs shows correctly on pages whose Content Security Policy blocks inline styles, and in Turbo apps it stays on the page when a frame link advances the URL or a refresh morphs the page, and no second copy comes back after Back.
