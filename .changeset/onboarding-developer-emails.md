A project's owners can email its setup steps to up to three developers. `sendDeveloperSetup` (`onboarding:sendDeveloperSetup` on Convex) returns a result for each address: `sent`, `already-sent`, `limit` with which limit, `suppressed`, or `invalid`. Each address gets one email per project, with no resends: asking again returns `already-sent`, unless the email `failed`, which sends a new one at once. A setup link opens only for the exact address its email went to, and a send to another address of the same inbox is its own. A person sends at most 5 developer emails a UTC day, and developer emails share each inbox's daily and the deployment's hourly invite email limits, counted when an email is reserved. A refused address records nothing and uses no limit. A project name or sender name with a web address in it (`://`, `www.`, or a domain such as `name.com`; a version such as `2.0`, or a name ending in a code file's ending that isn't also a top-level domain, such as `Next.js` or `index.html`, is fine) refuses the whole request with an `invalid` error that says to rename it. Emails come from Critiqs's address as "{name} via Critiqs" with replies to the sender, leave out the prototype's address (the setup page shows it after sign-in), and include the install commands when the stack is installable or unknown. When the sender is an admin of the project's organization, the developer is also invited to it as a member, without a separate invite email. Each `sent` result's `invite` says what happened to that invite, separately from the email: `created`, `pending` (already invited), `member` (already in it), `limit` (the organization's invites for the day ran out), or `none` (the sender isn't an admin). Sending again retries an unconfirmed email without inviting again: its `invite` reports the developer's state now, so an invite withdrawn since stays withdrawn. `projectSetup` (`onboarding:projectSetup` on Convex) gives the setup page of a message someone copied, which links to the project: its name, review address, and install commands for anyone signed in, the same rule as reading the project, and the saved stack with its commands (none for a stack Critiqs can't install in yet) only for the people who manage it; anyone else gets `stack: null` and the commands for an unknown stack. `developerSends` lists who a project sent setup steps to, for its owners, and `developerSetup` shows a setup link's project to the developer signed in with the exact address it was sent to. Each attempt at the mail service and its answer is recorded under the email's one key: the email is `sent` once one is accepted, `failed` once every attempt is refused (or its inbox opted out before the first), and otherwise `uncertain`, retried only under its own key within 23 hours of its first attempt and after that counted as possibly delivered and never sent again. Each email has a link to report it as unwanted; after a confirmation page, whose form posts back to the page's own address, that inbox gets no more developer or invite emails, including ones already queued. Setup links open the website named by `CRITIQS_WEB_URL` on Convex (default `https://critiqs.app`), or by the new `webUrl` option of `createCritiqsHandler`. On a self-hosted server, report links start with the new `publicUrl` option, the app's public address; without `webUrl` or `publicUrl`, it sends no setup emails. `/critiqs/config` reports `developerEmails`. Mail messages accept an optional display name and `Reply-To`; existing emails are unchanged. A self-hosted SQLite database upgrades on start.
