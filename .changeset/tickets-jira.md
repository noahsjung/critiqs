Jira Cloud joins Linear and GitHub Issues in Your trackers and tickets. **Connect Jira** asks for the Jira site (such as `your-team.atlassian.net`), then opens Atlassian's sign-in for it where the deployment has an Atlassian app, or takes an Atlassian API token with the person's email. Create ticket offers each project and issue type, asks for the fields the issue type requires (and names any it can't fill), sends the text as Atlassian Document Format, attaches the capture, adds the thread as a remote link, and suggests the site's labels that match the thread's tags. Link ticket searches by key or words. Project owners paste Jira templates in Tags and AI, under Tickets. Status comes back from the webhooks a Jira sign-in registers and from the check when a thread opens; Resolve when done works for Jira tickets. A person's webhook follows only the projects of their linked tickets that they may still review, worked out again at each daily renewal, which removes one that follows nothing; disconnecting removes their webhooks at Jira. A delivery's token must say when it expires (within the hour), and a delivery only says an issue changed on its site: Critiqs reads the issue's status from Jira with the linker's own token, at most 300 times a minute per site (429 past that). An issue Critiqs can no longer find in Jira keeps its last status, marked last known, never Deleted, since Jira answers a hidden issue as a missing one; an issue moved to another project is found by its old key and the link moves to its new key and project. A person's webhook is worked out, from tickets linked with the Jira account it is registered as, before their token is read at all. Deploy the matching backend; operators set `CRITIQS_JIRA_CLIENT_ID` and `CRITIQS_JIRA_CLIENT_SECRET` for sign-in.
